# 困难镜牢逐步寻路设计

## 目标

困难模式只能看见 Bus 所在列之外的两列节点，因此不能复用首次识别得到的整层路线。每成功走一步后，下一次寻路必须重新识别当前画面，并以新结果完整替换 `MirrorMap` 的地图和路线。普通模式保持现有缓存行为。

## 坐标与 Bus 行

逻辑坐标统一为 `(行, 列)`。地图上方、中间、下方三行分别为 `1`、`0`、`-1`，列从 Bus 所在列 `0` 向右递增。Bus 根据实际所在行分别使用 `(1, 0)`、`(0, 0)`、`(-1, 0)`。

`MirrorMap.bus_row` 保存当前 Bus 行，初始化值为 `None`；首次构图通过三位置探测确认行，成功进入下一节点后再根据实际目标更新为 `1`、`0` 或 `-1`。普通和困难模式后续构图都使用该行直接定位当前 Bus。`refresh_floor()` 只更新楼层并清空地图/路线，不修改已缓存的 `bus_row`。

Bus 定位统一由 `find_bus(bus_row=None)` 提供：未知行执行三位置探测，已知行只识别当前画面。构图前统一校验 Bus 行；`_snap_points_to_grid` 的 `bus_row` 是必填参数，且仅接受整数 `1`、`0`、`-1`，防止 `None` 或错误行进入坐标计算。

## 更新策略

两种模式都跳过旧的 Bus/enter 快捷入口并经过 `MirrorMap`。普通模式只在缓存不足时使用当前 `bus_row` 构图，之后逐个消费 `floor_route`；困难模式每次调用 `get_next_node_direction()` 都重新构图，并在识别成功后同时整体替换 `floor_map` 与 `floor_route`。进入节点后先更新 `bus_row` 并消费当前路线起点，旧图保留到下一次识别成功后再被原子替换；识别失败则清空两者。事件节点通过事件页标志确认成功，避免因没有 enter 按钮而漏掉 Bus 行更新。

## 验证

单元测试覆盖不同 Bus 行坐标、普通模式缓存、hard mode 快捷入口隔离、事件节点状态提交，以及困难模式使用更新后的 `bus_row` 全量替换地图与路线。
